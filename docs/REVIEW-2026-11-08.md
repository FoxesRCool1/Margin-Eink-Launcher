## 3. Other confirmed bugs, by area

### Storage and data

- Writing onto a path that is a folder moves the whole folder aside as `.old-N`. A restore zip with an entry named exactly `notes` triggers it (the check is top-folder name only). `core/storage/LocalFileStore.kt:145-161`; `BackupArchive.kt:127`.
- Legal hand-copied names are listed but unusable: leading or trailing spaces, `1: Intro.md` (colon as second character), backslash rewritten. They show with a blank title, the editor treats them as missing, backups skip them silently. `core/storage/RelativePaths.kt:19,22,27`.
- One bad entry in a hand-edited habits, habit log, routine or annotations file is dropped without a log line and deleted on the next save. `keepUnreadable` only runs when the whole file fails. `log.csv` has no rescue at all. `core/habits/HabitsFile.kt:55-69`; `HabitLogFile.kt:39-45`; `core/routine/RoutineFile.kt:41-52`; `core/reading/BookAnnotations.kt:94-96`.
- Habits and routine ignore the Boolean from the save and report the new state anyway. `core/habits/HabitsRepository.kt:75,82,94,112,120,153`; `core/routine/RoutineRepository.kt:76,91,96,123`.
- Orphan `.part-*`, `.old-*` and `.renaming` files are not filtered by `LocalFileStore.list*`: they show as rows in Writing, go into backups, and are never swept.
- `folders.json`: a transient read failure (not "missing") loads as empty, and the next Pin or Hide writes an empty file over the real one. A malformed `folders` value parses as valid with entries dropped, so `keepUnreadable` never runs. `ui/apps/AppFoldersRepository.kt:29`; `core/apps/AppFolders.kt:123-141`.
- Journal: an unreadable day file reads as `""` (`.orEmpty()`), so a later save overwrites it. `ui/journal/JournalScreen.kt:177`.
- Reading log: unlocked read-modify-write; two readers pausing together (split) can lose a line. `core/reading/ReadingRepository.kt:81-94`.
- CJK titles: the 120 limit is characters, Android's is 255 bytes. About 77 CJK characters fail to create. Same for book ids (about 85). `core/storage/StorageLayout.kt:146`.
- `BooksRepository.delete` deletes the annotations JSON by the cut name and the ink folder by the raw id, so for stems over about 112 characters the folder (PDF ink, handwritten cards) stays. Two long names sharing their first 120 characters share one notes file. `core/books/BooksRepository.kt:136-137`; `StorageLayout.kt:52,123`.
- `PdfInkRepository.annotatedPages()` throws on a hand-copied `page-0000.strokes` (`require(pageNumber >= 1)` escapes), uncaught in the Ink Pages panel and in export. `core/pdf/PdfInkRepository.kt:62-70`.
- Writing tab reads every `.md` in full on each refresh. `core/notes/NotesRepository.kt:52-63`.
- `BookMetadata` reads a whole zip entry before applying its 2 MB cap; scans the zip twice with `ZipInputStream`; a `<!DOCTYPE` anywhere in the OPF rejects it; percent-escaped OPF paths are not matched. `core/books/BookMetadata.kt:40-106`.
- Small: `NoteText.titleFrom` doc says heading wins, code takes first non-empty line; `freePath` splits folder names on a dot (`Drafts v1.2` becomes `Drafts v1 2.2`); `PartOfDay` wrong for a boundary of 12 or later; JSON `1e400` written back as `0`.

## 4. UI, UX and e-ink rules

The hard rules hold: no animation API, no window or dialog transition, no ripple, no Lazy list or scroll modifier on a user screen, no Material, no colour literal outside black, white and the documented greys, no raw Dialog or BasicTextField, no em dash anywhere, every activity calls `ScreenWindow.attach`, every `PagedList` has a `rowHeight`, no coloured pixel in any of the 169 screenshots.

What does not hold, ranked by visibility:

1. Month view cells under 56 dp (item 14 above).
2. Home status line (Wi-Fi, battery) is a 28 dp sliver in a 320 dp half: four 56 dp buttons with 4 dp gaps leave nothing for the `weight(1f)` box. `ui/home/HomeScreen.kt:274-300`. See `split_home_choice_land.png`.
3. Touch targets with 0 to 4 dp between them, though `EinkDimens.targetGap = 12.dp` exists: pane Swap and Close (`SplitLayout.kt:162-167`, a slip closes the split), scaffold Split and Rotate (`ScreenScaffold.kt:158-159`), Home bottom row, settings tabs, search field and button, and the ink and PDF tool rails at minimum size (`InkNoteActivity.kt:423,448`; `PdfReaderScreen.kt:109,131`).
4. Small grey text (rule: grey is for large inactive text only): empty states at 13 sp caps (`PagedList.kt:160`), authors (`ReadingScreen.kt:258,271`), "4 APPS" tags, habit streaks, routine detail, word counts, highlight summary, log tags, and the 20 dp grey Turn-the-screen icon on every screen. Either black at that size or 17 sp or more.
5. Text selection colour is `Ink.copy(alpha = 0.25f)`, an alpha wash. `design/EinkTheme.kt:29`. Document it or draw an underline.
6. Text fields do not override `LocalTextToolbar` or the selection handles, so a long press likely shows the platform floating toolbar and magnifier (animated). The EPUB reader handles this with its own `ActionMode`; no text field does. `design/components/EinkTextField.kt:164-205`. Needs the tablet.
7. Word buttons where the rule says icons: Update, Install, Add Token, Allow Installs, Change Token, Paste here, Export as Markdown. The journal word count is an unbordered button that cycles the daily goal on tap; nothing shows it is a button. `ui/journal/JournalScreen.kt:675-684`.
8. Dialogs have no height cap and `ConfirmDialog` has no `maxLines`; at 1.5x font with a long title the Yes/No buttons can fall off the bottom on its side. `design/components/EinkDialog.kt`; `ConfirmDialog.kt:73,75`.
9. Screens outside the screenshot test's three views: Update (upright only), EPUB chrome (upright only), Log (no split), Device Test and Pen Test (none). Only Home is shown at a large font.
10. 14 stale screenshots from the old multi-page Settings are still in `app/build/outputs/roborazzi/` (`settings_menu*`, `settings_look*`, and so on) and show help lines and version 1.0.1.

## 5. Features: promised vs built

Almost every row of plan.md section 6 "Version 1" exists. Gaps that matter:

1. Backup scope (item 15).
2. Routine items cannot be given a target. `RoutineItem.target` and `HomeActivity.tabOf` support `read/write/journal/apps/app:<pkg>`, but the only add dialog passes a label. Every user-made item shows "Done", never "Start". `ui/journal/JournalScreen.kt:558-573`; `core/routine/RoutineItem.kt:6-13`.
3. Day boundary hour is not a setting. `HabitsRepository.setDayBoundaryHour` has no caller outside a test. Plan Step 9 promised it.
4. Neither reader has search in the book, bookmarks or go-to-percent. PDF has no outline, text selection or typed note per page. Global Search reads notes, journal and highlights, not book text or titles.
5. Daily reading goal is set only in the EPUB sheet and never shown in the PDF reader; a PDF-only reader sees a goal line in the library they cannot change.
6. Exports land in `Android/data/<pkg>/files/Margin/exports/`, which Android 11+ file managers cannot open. No `ACTION_SEND`, no copy to Downloads, and `exports/` is not in the backup. No `ACTION_VIEW` or `ACTION_SEND` filter for epub or pdf, so the picker is the only way in.
7. "Device Test" is visible in release builds on ViWoods (no `BuildConfig.DEBUG` gate). "Try the Pen" is public by design; the engineering screen is not. `ui/settings/SettingsScreen.kt:305-318`.
8. Searching handwriting: ink notes by name only; handwritten journal days not searched at all. `core/search/SearchSource.kt:46-75`.
9. Ctrl+N works on Home only, though the comment says "from anywhere".

Half built: Continue and Before skip the Journal; no quick handwritten page in a narrow half; swipes on Home have no hint and both targets have buttons; split state lost on process death (intended, README silent); typed notes have no undo, no file name shown, no preview; handwritten notes have no zoom, no page overview (previews are stored and never shown), no jump to page; Force Refresh only in Settings and Auto Refresh covers tab and split changes only; dictionary choice has no settings row; archived habits cannot be seen.

Gaps a user would expect, that fit the design: search in book (EPUB first), bookmarks and go to percent, `settings.json` in the backup, share for exports and open-with for books, a target picker for routine items, a day boundary row, Force Refresh in the reader menu, typed-note undo, page overview for ink notes, reading statistics from the CSV that already exists, a list of archived habits, journal export and browse list.

Dead code in main with no caller: `BooksRepository.lastRead`, `DataRepository.listNotes`, `InkStroke.withPages/withTemplate`, `FastPenSession.isRunning`, `InkCanvasView.setBackdrop/pageBoxInView`, `DataRepository.buildIndex` and `LibraryIndex` (test only), `StorageBenchmark` (debug caller, ships in release), `DemoActivity` (ships in release behind a debug-gated row). No TODO or FIXME in source. No old name or em dash in any user string.
